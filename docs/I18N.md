# I18N

## Idiomas soportados

Los locales activos viven en `config/locales.php`:

| Locale | Idioma | País sugerido |
| --- | --- | --- |
| `es` | Español | MX |
| `en` | English | US |
| `pt` | Português | BR |
| `fr` | Français | FR |

El locale default es `es`.

## Regla de aprobación

Ningún módulo nuevo debe aprobarse si tiene textos visibles hardcodeados. Todo texto visible en Blade, componentes Livewire, validaciones, botones, tablas, modales, menús y estados de UI debe resolverse con archivos `lang/`.

Usa:

```blade
{{ __('Guardar') }}
```

No uses:

```blade
Guardar
```

## Agregar claves

1. Agrega el texto base en `lang/es.json`.
2. Agrega la misma clave en `lang/en.json`, `lang/pt.json` y `lang/fr.json`.
3. Si falta traducción final, usa el prefijo `[PENDING TRANSLATION]` temporalmente.
4. Ejecuta `php artisan i18n:audit`.

Convenciones:

- Reutiliza claves existentes cuando el texto visible sea igual.
- Mantén frases completas como clave en JSON para textos simples de Blade.
- Usa claves de grupo PHP solo cuando el módulo necesite estructura, por ejemplo `pricing.valid_from`.
- No traduzcas valores técnicos, códigos, URLs, nombres de proveedores, códigos ACRISS, IDs, moneda de negocio ni datos ingresados por usuarios.

## Agregar idioma

1. Agrega el locale a `config/locales.php`.
2. Actualiza `App\Support\SupportedLocale`.
3. Crea `lang/{locale}.json`.
4. Agrega selector/validación si aplica.
5. Ejecuta `php artisan i18n:missing {locale} --write`.
6. Ejecuta `php artisan i18n:audit`.
7. Agrega pruebas para el nuevo locale.

## Formato regional

Fechas, horas y números deben pasar por helpers:

```blade
{{ format_date($date) }}
{{ format_datetime($date) }}
{{ format_number($value) }}
{{ format_money($amount, $currency) }}
```

No uses `date('d/m/Y')`, `number_format()` ni monedas hardcodeadas en vistas.

La moneda de negocio no se infiere del idioma. Debe venir del proveedor, país, tarifa o contexto de negocio.

## Excel

Las plantillas de tarifas se generan por locale:

```text
storage/app/templates/supplier-prices-es.xlsx
storage/app/templates/supplier-prices-en.xlsx
storage/app/templates/supplier-prices-pt.xlsx
storage/app/templates/supplier-prices-fr.xlsx
```

Los encabezados visibles se traducen para el usuario, pero la importación se procesa con claves internas como `office_code`, `vehicle_class`, `base_price`, `currency`, `valid_from` y `valid_to`.

Reglas:

- No uses encabezados traducidos como lógica de negocio.
- Agrega claves internas, `translation_key` y aliases de encabezados en `config/imports.php`.
- Mantén las claves internas estables.
- Los errores de importación deben usar `__()` y el locale del usuario.
- Los reportes de error descargables deben mostrar resumen y mensajes traducidos.

## Auditoría

```bash
php artisan i18n:audit
php artisan i18n:missing
```

`i18n:audit` falla si encuentra:

- Textos visibles hardcodeados en Blade.
- Claves faltantes entre `es`, `en`, `pt` y `fr`.
- Llamadas a traducciones inexistentes.
- Locales no soportados.

`i18n:missing` compara `lang/es.json` contra los demás idiomas.

Para crear claves faltantes:

```bash
php artisan i18n:missing en --write
```

Para limpiar prefijos pendientes duplicados:

```bash
php artisan i18n:missing en --normalize-pending
```

## Pruebas

Ejecuta:

```bash
php artisan test --compact tests/Feature/LocalePreferenceTest.php tests/Feature/I18nQualityTest.php
```

La auditoría también corre en CI con:

```bash
php artisan i18n:audit
```

## Checklist de release

Antes de liberar cambios i18n:

- Ejecutar `php artisan test --compact`.
- Ejecutar `php artisan i18n:audit`.
- Probar login y registro con `es`, `en`, `pt` y `fr`.
- Probar descarga y carga de Excel por idioma.
- Probar validaciones traducidas.
- Probar emails y notificaciones visibles para usuario.
- Probar fallback seguro a `es` con locale vacío o inválido.
- Confirmar que `POST /settings/locale` requiere usuario autenticado y respeta rate limit.

## Qué se traduce

Se traduce todo texto visible de interfaz: navegación, encabezados, botones, labels, placeholders visibles, mensajes de validación, estados, modales, tablas, reportes, promociones, vigencias, totales y textos de ayuda.

## Qué no se traduce

No se traducen nombres propios, marcas, códigos externos, URLs, identificadores técnicos, moneda de negocio, valores cargados por proveedor, datos de reservas, IDs, códigos ACRISS ni contenido generado por usuarios.
